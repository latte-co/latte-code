# v0.1 Engineering Baseline

## 文档状态

本文是 Fluxcode `v0.1` 的里程碑工程基线目标，不是 `design/` 下的模块设计。它定义 `v0.1` 要真正跑通 `fluxcode run "实现一个贪吃蛇游戏"` 这类任务时必须具备的落地细节：AI Provider、配置文件、tools、prompt 管理和 context 压缩。

英文对应文档：[`docs/en-US/milestones/targets/v0.1-engineering-baseline.md`](../../../en-US/milestones/targets/v0.1-engineering-baseline.md)。

## 1. 目标

`v0.1` 的工程目标是：在一个已有应用基础的本地仓库中，Fluxcode 能通过 CLI 调用真实模型，读取上下文，修改源码，运行已声明验证命令，并输出可审查 handoff。

这要求 `v0.1` 不只具备抽象 loop，还必须具备以下最小工程能力：

- 一个真实可用的 model provider adapter。
- 一个稳定的 `ModelClient` 内部协议，用于屏蔽不同模型厂商差异。
- 一个可解释、可覆盖、无 secrets 的 JSONC 配置文件。
- 一组足以完成小型代码任务的基础 tools。
- 可版本化、可测试的 phase prompts。
- 不依赖完整 transcript 的 context budget / compaction 策略。

## 2. AI Provider 方案

### 2.1 内部协议先行

Fluxcode 内部只依赖 `ModelClient`，不让业务 loop 直接依赖 OpenAI、Anthropic、Claude Code、MCP 或任意厂商协议。

```ts
type ModelTurn =
  | { type: "message"; content: string }
  | { type: "tool_calls"; content?: string; toolCalls: ToolCall[] };

interface ModelClient {
  generate(request: ModelRequest): Promise<ModelTurn>;
}
```

Provider adapter 的职责是把外部协议转换成这个 canonical form：

| 外部差异 | 内部归一 |
| --- | --- |
| OpenAI tool calls / Anthropic tool_use 命名不同 | 统一为 `ToolCall[]` |
| streaming / non-streaming 差异 | v0.1 先支持 non-streaming，streaming 后续只影响 UI |
| system / developer / user message 差异 | 统一为 `ModelMessage[]`，adapter 内部映射 |
| token 参数命名差异 | 统一为 `maxOutputTokens`、`temperature` |
| JSON mode / tool choice 支持差异 | v0.1 不依赖强 JSON mode，使用 prompt + schema repair 兜底 |

### 2.2 v0.1 Provider 优先级

| Priority | Provider | 用途 | 说明 |
| --- | --- | --- | --- |
| P0 | `fake` | 单元测试和集成测试 | 已存在，必须保留 |
| P0 | `openai-compatible` | 第一类真实模型适配 | 兼容 OpenAI、Azure OpenAI、兼容 OpenAI API 的本地或网关模型 |
| P1 | `anthropic-compatible` | Claude / Anthropic Messages API | 用于更贴近 Claude Code 的 tool_use 语义 |
| P2 | `custom-command` | 本地命令或企业内部模型代理 | 仅在有实际需求时实现 |

`v0.1` 不需要抽象成 LangChain / Vercel AI SDK 这类上层框架。优先保持 adapter 小而透明，便于调试 tool call 和权限问题。

### 2.3 Provider 失败语义

| 场景 | 处理 |
| --- | --- |
| 缺少 API key | 启动前失败，并提示缺少的 env 名称 |
| 429 / rate limit | 记录 provider error，可按配置有限重试 |
| tool call JSON 无法解析 | 进入一次 schema repair turn，仍失败则 block 当前 phase |
| 模型不支持 tools | 启动前或 phase 开始前失败，不降级为纯文本执行 |
| 输出超长 | 截断摘要并记录 truncation，不把长输出继续塞回 prompt |

## 3. Config 配置设计

### 3.1 配置文件定位

配置文件是 project-local runtime policy，不是 secrets 存储。推荐路径：

```text
fluxcode.config.jsonc
```

规则：

- API key 只通过环境变量引用，例如 `apiKeyEnv`。
- 默认配置必须能跑 `fake` provider 测试。
- 真实 provider 必须显式设置为 default，不能意外使用用户机器上的全局 secret。
- 配置 merge 顺序为 default config -> project config -> CLI flags。

### 3.2 v0.1 推荐配置结构

```jsonc
{
  "schemaVersion": 1,
  "models": {
    "default": "primary",
    "providers": {
      "fake": { "type": "fake", "model": "fake-scripted" },
      "primary": {
        "type": "openai-compatible",
        "model": "gpt-5.5",
        "baseUrl": "${FLUXCODE_MODEL_BASE_URL}",
        "apiKeyEnv": "FLUXCODE_MODEL_API_KEY",
        "temperature": 0.2,
        "maxOutputTokens": 8192
      }
    }
  },
  "runtime": {
    "maxPhaseSteps": 8,
    "maxRepairTurns": 1,
    "stopOnVerificationFailure": true
  },
  "prompts": {
    "profile": "default-code-agent-v1",
    "language": "zh-CN"
  },
  "context": {
    "maxPromptBytes": 120000,
    "maxToolResultBytes": 32768,
    "recentStepCount": 6,
    "preserve": ["task", "acceptance", "constraints", "changedFiles", "verification"]
  },
  "permissions": {
    "defaultMode": "ask",
    "allowReadOnlyTools": true,
    "mutatingTools": "ask",
    "highRiskTools": "deny",
    "trustedDirectories": ["."],
    "denyGlobs": ["**/.env*", "**/node_modules/**", "**/.git/**"]
  },
  "tools": {
    "enabled": ["list_directory", "read_file", "search", "edit_file", "write_file", "shell_exec", "read_project_manifest"],
    "disabled": [],
    "maxOutputBytes": 32768,
    "shell": {
      "defaultTimeoutMs": 120000,
      "allowCommands": ["npm test", "npm run build", "npm run test:coverage"],
      "requireApprovalFor": ["network", "install", "delete", "git-write"]
    }
  },
  "session": {
    "store": "filesystem",
    "directory": ".fluxcode/sessions",
    "autosave": true,
    "maxTranscriptBytes": 1048576
  },
  "evidence": {
    "store": "filesystem",
    "directory": ".fluxcode/evidence",
    "captureToolInputs": "summary",
    "captureToolOutputs": "summary",
    "maxEvidenceBytes": 262144
  }
}
```

当前 `src/config/types.ts` 已有 `models`、`permissions`、`tools`、`session`、`evidence`、`coverage`。实现 `v0.1` 时需要补充 `runtime`、`prompts`、`context` 和 `tools.shell.allowCommands`。

## 4. Tools 最小集合

`v0.1` 的 tools 目标不是多，而是足以完成小型代码任务并具备安全边界。

| Tool | Priority | Mutating | 用途 | 当前状态 |
| --- | --- | --- | --- | --- |
| `list_directory` | P0 | no | 查看仓库结构 | 已有 |
| `read_file` | P0 | no | 读取源码、测试、配置 | 已有 |
| `search` | P0 | no | 搜索符号、文本和测试入口 | 已有 |
| `edit_file` | P0 | yes | 基于 old/new 或 range 的局部修改 | 需要新增 |
| `write_file` | P0 | yes | 创建新文件或完整覆盖小文件 | 已有，但应限制覆盖风险 |
| `shell_exec` | P0 | yes | 运行声明验证命令 | 已有，但需命令 allowlist |
| `read_project_manifest` | P0 | no | 读取 package / tsconfig / test config 摘要 | 需要新增，可先内部实现 |
| `git_diff` | P1 | no | 生成 changed files / diff summary | 需要新增 |
| `diagnostics` | P1 | no | LSP / TypeScript diagnostics | 后续实现 |

### 4.1 为什么需要 `edit_file`

只有 `write_file` 会把模型推向整文件重写，风险较高。`edit_file` 应支持最小局部修改：

```ts
type EditFileInput =
  | { path: string; mode: "replace"; oldText: string; newText: string; replaceAll?: boolean }
  | { path: string; mode: "insert_after" | "insert_before"; anchor: string; text: string };
```

约束：

- `oldText` 必须唯一匹配，除非 `replaceAll=true`。
- 修改前记录 file hash 或 mtime，用于 stale write 防护。
- 修改后返回 changed bytes、matched range 和 summary。

### 4.2 Shell 命令策略

`shell_exec` 不能是任意 shell。v0.1 只允许：

- 配置里 `tools.shell.allowCommands` 明确列出的命令。
- 从 project manifest 中声明的 scripts，例如 `npm test`、`npm run build`。
- 用户本轮明确确认的命令。

默认阻止：

- install：`npm install`、`pnpm add`、`pip install`。
- delete：`rm -rf`、批量删除。
- network：curl、wget、远程脚本。
- git write：commit、push、reset、checkout、rebase。

## 5. Prompt 管理

Prompt 不应散落在代码字符串里。v0.1 需要一个轻量 prompt registry。

推荐结构：

```text
src/prompts/
  system.ts
  phases/
    intake.ts
    understand.ts
    plan.ts
    edit.ts
    verify.ts
    handoff.ts
```

每个 prompt 定义：

```ts
type PromptTemplate = {
  id: string;
  version: string;
  phase: AgentPhase;
  render(input: PromptRenderInput): ModelMessage[];
  expectedOutput: string;
};
```

Prompt 管理规则：

- system prompt 只描述 agent 身份、工具边界、安全约束和 artifact 输出规则。
- phase prompt 描述当前阶段目标、允许工具、输出 schema 和失败处理。
- 不把大段历史 transcript 直接拼进 prompt；只传 `TaskSpec`、phase artifacts、recent steps 和必要 evidence summary。
- prompt id 和 version 写入 `StepTrace`，便于复现。
- 自定义 prompt 后续可支持，但 v0.1 不开放任意项目 prompt 覆盖安全规则。

## 6. Context 压缩

`v0.1` 不需要复杂 memory 系统，但必须避免 transcript 无限增长。

### 6.1 Context lanes

每次模型调用由四类上下文组成：

| Lane | 内容 | 是否可压缩 |
| --- | --- | --- |
| Task lane | `TaskSpec.objective`、acceptance、constraints、nonGoals | 不可丢失 |
| Artifact lane | `ContextPack`、`ChangePlan`、`PatchSummary`、`VerificationResult` | 可摘要但不能丢引用 |
| Evidence lane | 工具结果摘要、文件引用、命令输出摘要 | 可压缩 |
| Recent loop lane | 当前 phase 最近 N 步 ReAct 观察 | 可滑动窗口 |

### 6.2 压缩策略

当 prompt 超过 `context.maxPromptBytes` 时，按顺序处理：

1. 截断长工具输出，只保留 summary、references、truncated marker。
2. 压缩旧 `StepTrace` 为 phase summary。
3. 保留 changed files、verification failures、user constraints 和 open blockers。
4. 对已读文件内容只保留路径、原因和必要片段。
5. 如果仍超预算，block 当前 phase，要求缩小任务范围。

禁止压缩掉：

- 用户验收条件。
- 用户明确非目标。
- 权限拒绝或待确认项。
- 修改文件列表。
- 验证失败摘要。

## 7. 当前代码缺口

| 缺口 | 影响 | v0.1 处理 |
| --- | --- | --- |
| `openai-compatible` adapter 尚未实现 | CLI 默认只能 fake | 实现真实 provider adapter |
| `config-schema` 只校验顶层 | 配置错误发现晚 | 补充 runtime / prompts / context / shell allowlist 校验 |
| 缺少 `edit_file` | 真实修改容易整文件覆盖 | 新增局部编辑工具 |
| `shell_exec` 缺少 allowlist | 命令风险高 | 增加 declared command discovery 和 allowlist |
| prompt 硬编码在 `agent-loop.ts` | 难测试、难版本化 | 新增 prompt registry |
| context 依赖 transcript | 长任务不可控 | 新增 context builder / compactor |
| CLI 输出仍是 loop result | 缺少 handoff | 输出 `AgentHandoff` 和 artifact paths |

## 8. v0.1 实现顺序

1. 实现 `openai-compatible` `ModelClient` adapter。
2. 扩展 config：`runtime`、`prompts`、`context`、`tools.shell.allowCommands`。
3. 新增 prompt registry 和 phase prompts。
4. 新增 `PhaseRunner` 和 artifact schema 校验。
5. 新增 `edit_file`、`read_project_manifest`，收紧 `shell_exec`。
6. 新增 context builder / compactor。
7. CLI `run` 输出 `AgentHandoff`。
8. 用 `FakeModelClient` 覆盖 happy path、provider error、permission ask、verification fail、context overflow。

## 9. 验收

- 配置真实 provider 后，`fluxcode run "实现一个贪吃蛇游戏"` 不再返回 fake 默认消息。
- 对已有 Web / frontend 仓库，agent 能创建或修改源码文件。
- agent 能运行已声明测试或构建命令，并把结果写入 handoff。
- 无框架或缺少依赖决策时，agent 明确 block 并请求确认。
- prompt、context、tools、provider、permission 决策都能在 event log 或 step trace 中追溯。
